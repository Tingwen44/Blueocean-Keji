## Phase A · 见顶/见底信号分类 + 贪婪指数实时 (1.5h)

**当前问题**:
  - Step ⑦ 7 个 trigger 没标"见顶 vs 见底"
  - 情绪值是规则推断, 不是真实数据

**改动**:

### A.1 信号分类重构

每个 `TopBottomSignal` 加 `signal_type: "top" | "bottom" | "neutral"` 字段

7 个 trigger 重新分类:

| 信号 | 类型 | 含义 |
|---|---|---|
| 50d/200d 死叉 (50d 下穿 200d) | **bottom** | 中期买入信号 |
| 50d/200d 金叉 | **top** 警告 | 中期过热信号 |
| RSI > 70 | **top** 警告 | 超买 |
| RSI < 30 | **bottom** | 抄底信号 |
| 距 52w 高 > 20% | **bottom** | 折价 |
| 距 52w 高 < 5% | **top** 警告 | 接近高点 |
| 成交异常 (>3x 均量) | **neutral** | 双向, 看具体方向 |

UI 改造: 左侧"进度"栏的 Step ⑦ 分两个表展示:
  - "⚠️ 见顶警告" 表 (top signals)
  - "✅ 见底信号" 表 (bottom signals)
  - 情绪条放最上面, 实时数值

### A.2 贪婪指数实时拉取

数据源: CNN Fear & Greed Index API
URL: `https://production.dataviz.cnn.io/index/fearandgreed/graphdata`
(免费, 不用 API key, 实时更新)

返回格式示例:
```json
{
  "fear_and_greed": {
    "score": 73,
    "rating": "Greed",
    "previous_close": 71,
    "previous_1_week": 65
  }
}
```

后端:
  - 新增 `/api/market/sentiment` 端点
  - 内部缓存 10 分钟 (避免反复拉)
  - 失败时 fallback 到规则推断

前端:
  - 顶部"进度"栏情绪行加真实数值 (73 / Greed)
  - 加色条: 0-25 红(extreme fear) / 25-45 橙 / 45-55 黄 / 55-75 浅绿 / 75-100 深绿(extreme greed)

## Phase B · 蓝海框架 + 信息差清单 (1.5h)

**当前问题**:
  - mainland-subjective-analysis skill 提炼了 MPEVL 5 维 + 5 大方法, 但前端没暴露
  - "信息差 S/A/B/C 4 级"框架用户没看到自动评估

**改动**:

### B.1 蓝海框架展示

加新 Tab "📐 蓝海框架" 在主分析区下方 (跟 8 步并列, 不破坏现有结构)

展示内容:
  - **MPEVL 5 维**: Macro/Policy/Earnings/Valuation/Liquidity 各自打 0-10 分 (基于 Step ② ⑤ ⑦)
    - M (宏观) = 来自 FRED 的 GDP/CPI/利率打分
    - P (政策) = 日历+事件打分 (中期选举/鲍威尔)
    - E (盈利) = Step ② 盈利维度
    - V (估值) = Step ② 估值维度
    - L (流动性) = 50d MA/200d MA/ADV
  - **5 大方法**: 产业链瓶颈/日历事件/轮动/专家访谈/见顶见底 → 显示每个方法适用度评分

### B.2 信息差 4 级自动评估

基于 yfinance 数据 + LLM 综合, 自动给信息差等级:

| 等级 | 定义 | 自动判断规则 |
|---|---|---|
| **S (一手)** | 供应商访谈/管理层沟通/订单数据 | yfinance 拿不到 → 默认 0 |
| **A (二手)** | 13F 持仓变动/分析师预期差/大单流向 | 部分可拉, LLM 推断 |
| **B (公开)** | 主流财经媒体报道/雪球讨论热度 | Google Trends + 媒体 |
| **C (低质)** | yfinance 财报数据/价格 | 永远有 |

UI:
  - 4 个标签 + 颜色 (S=金 / A=银 / B=蓝 / C=灰)
  - 每个标签下面列该等级的具体信息源 + 数量
  - 综合评估: "信息差评分 X/10, 当前主要依赖 C/B 级数据, 建议补充 S/A 级"

## Phase C · 轮动定位量化 (2h) ← 重点, 最复杂

**当前问题**:
  - Step ⑥ 4 个字段全手填, 用户没动力

**改动**: 自动算, UI 显示结果 + 允许用户改

### C.1 量化指标 (4 个)

#### ① 板块轮动位置 (leading/mid/late/catchup)

数据源: 板块 ETF 的相对强弱 (vs 标普 500)
  - 拉板块 ETF (XLK/XLV/XLF/XLE/XLY/XLP/XLI/XLU/XLB/XLC) 1m/3m/6m 涨跌幅
  - 当前 ticker 所属板块 ETF vs SPY 的 1m/3m 相对强弱
  - 算法:
    - 相对强弱 > +10% → `leading` (板块超额收益)
    - 0% ~ +10% → `mid`
    - -10% ~ 0% → `late` (板块跑输)
    - < -10% → `catchup` (板块低谷, 但个股不一定差)

#### ② 板块资金热度

数据源: 板块 ETF 的 20 日均成交额 vs 60 日均成交额
  - 比率 > 1.5 → 资金涌入
  - 0.8-1.5 → 正常
  - < 0.8 → 资金流出

#### ③ 谷歌指数 (Google Trends)

数据源: Google Trends API (或 pytrends 库, 免费但有限速)
  - 拉 ticker + 公司名过去 30 天 / 90 天搜索热度
  - 与 1 年前同期对比
  - 比率 > 2.0 → 关注度暴增
  - 0.5-2.0 → 正常
  - < 0.5 → 关注度下降

#### ④ 个股相对表现

数据源: ticker 1m/3m/6m 涨幅 vs SPY 同周期
  - 跑赢 10%+ → "强势"
  - -10%~+10% → "中性"
  - 跑输 10%+ → "弱势"

### C.2 评分算法 (0-100)

```
position_score = (
    板块相对强弱分 (0-25) +
    资金热度分 (0-25) +
    谷歌指数分 (0-25) +
    个股相对表现分 (0-25)
)
```

映射到 4 档:
  - 80+ → `leading` + 标签"高确信领涨"
  - 60-80 → `mid` + "中段持有"
  - 40-60 → `late` + "末段谨慎"
  - < 40 → `catchup` + "低谷或补涨"

### C.3 UI

Step ⑥ 改成混合:
  - 顶部: 自动计算的 4 档判断 + 总分 (灰底显示, 可改)
  - 4 个子指标各一行, 显示数值 + 评分 (可展开看 raw data)
  - "轮动链" "资金流" 仍可手填 (LLM 辅助, 留接口)

## Phase D · 风险定价自动评分 (2.5h) ← 最重

**当前问题**:
  - Step ⑧ 风险全手填

**改动**: 4 类风险自动算分, UI 仍允许用户加自定义风险

### D.1 4 类风险

#### ① 宏观风险 (Macro Risk, 0-10)

数据源: FRED 宏观数据 (联储利率 / CPI / 失业率 / 10Y yield / VIX)
算法:
  - 利率分位 > 80% → +3 (高息环境)
  - CPI YoY > 4% → +2
  - VIX > 25 → +2
  - 失业率上升趋势 → +1
  - 10Y-2Y 倒挂 → +2
  - 总分上限 10, 越高越风险

#### ② 行业风险 (Sector Risk, 0-10)

数据源: 板块 ETF (XLK etc.) 历史数据
算法:
  - 板块 1y 跌幅 > 30% → +3
  - 板块 P/E 分位 > 80% → +2
  - 板块波动率 (60d std) > 40% → +2
  - ticker 在板块内权重 (市值占比) > 30% → +1
  - 集中度风险 (板块 Top3 公司占比 > 60%) → +2

#### ③ 竞争对手风险 (Competitive Risk, 0-10)

数据源: yfinance 行业 peers (从 ticker.sector 找)
算法:
  - 行业 HHI (赫芬达尔指数) 高 (集中度低/竞争激烈) → +3
  - ticker 毛利率 < 行业中位数 → +2
  - ticker 收入增速 < 行业中位数 → +2
  - ticker R&D / Revenue < 行业中位数 → +1
  - 行业 Top 3 集中度 (CR3) < 30% → +2

#### ④ 公司内部风险 (Internal Risk, 0-10)

数据源: yfinance 财务数据 (StockSnapshot 已有)
算法:
  - 流动比率 < 1.0 → +3 (短期偿债危机)
  - 负债/股东权益 > 200% → +2
  - 自由现金流持续 4 季为负 → +2
  - 经营现金流 / 净利润 < 0.5 → +1 (盈利质量差)
  - 内部人持股 < 5% → +1
  - 高管近期减持 → +1

### D.2 综合风险定价

```
总风险分 = max(宏观, 行业) + 竞争 + 公司内部
  (宏观和行业取最大, 因为是"系统性"vs"非系统性"的二分)
```

映射:
  - 0-4: **低风险** (green)
  - 5-7: **中风险** (yellow)
  - 8-10: **高风险** (red)
  - 10+: **极高风险** (deep red, 警示)

### D.3 UI 改造

Step ⑧ 改为:
  - 顶部: 综合风险等级 + 4 类风险 0-10 雷达图 (用 SVG, 不用 chart library)
  - 4 个分类各一个折叠区, 展开看具体 trigger + 数值
  - 仍保留"添加自定义风险"按钮 (用户加自己的 edge case)
  - 止损价/止损 % 仍手填 (无法自动)

## 优先级建议

```
A: 1.5h    见顶/见底 + 贪婪指数     ← 立刻有感知, 改 UI 小
B: 1.5h    蓝海框架 + 信息差 4 级   ← 知识沉淀, 但工作量大
C: 2.0h    轮动定位量化             ← 最有价值 (用户要的核心)
D: 2.5h    风险定价自动评分         ← 工作量最大
─────────────────────────────────
    7.5h 总
```

**推荐执行顺序**: A → C → D → B
  - A 最快最容易, 立刻给你"贪婪指数"实时值, 体验好
  - C 是用户最关心的, 但要做量化算法
  - D 工作量最大, 单独 1 个 phase
  - B 是知识展示, 重要但 ROI 偏低 (偏展示性)

**如果你想换顺序, 我可以调**。每个 phase 独立 commit, 独立验收, 失败不会阻塞其他 phase。
